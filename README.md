# REST Microservices Bughunt (ІДЗ)

Цей проєкт містить виправлену мікросервісну архітектуру, що складається з трьох сервісів на базі FastAPI: `auth-service`, `product-service` та `order-service`.
У рамках індивідуального завдання було знайдено та виправлено низку критичних помилок безпеки, логіки та міжсервісної взаємодії.

## 🛠 Виправлені баги
1. **Auth Service:**
   * Змінено метод ендпоїнта `/login` з `GET` на `POST` для безпечної передачі облікових даних.
   * Додано Pydantic-схему для валідації вхідних даних при логіні.
   * Виправлено статус-код для неавторизованого доступу (`401 Unauthorized` замість `200 OK`).
   * Додано перевірку валідності самого токена (формат підпису та наявність користувача в базі), а не лише наявність заголовка `Bearer`.
   * Налаштовано зчитування токена із заголовка `Header`, а не з параметрів URL.

2. **Product Service:**
   * Виправлено тип даних для ціни (`price`) з рядка на число (`float`) за допомогою Pydantic-схеми.
   * Налаштовано повернення коректного статусу `404 Not Found` (замість `200 OK`) при запиті неіснуючого товару.

3. **Order Service:**
   * Реалізовано обов'язкову перевірку авторизації через `auth-service` перед створенням замовлення (відхилення запитів із підробленими токенами зі статусом `401`).
   * Додано перевірку наявності товару (`inStock`) через `product-service` перед оформленням (заборона продажу товарів, яких немає на складі, зі статусом `400 Bad Request`).

## 🚀 Як запустити проєкт
Для запуску всіх мікросервісів локально потрібен Docker.

```
docker compose up -d --build

```

Сервіси будуть доступні за такими адресами:
* Auth Service: `http://localhost:8001`
* Product Service: `http://localhost:8002`
* Order Service: `http://localhost:8003`

## 🧪 Запуск тестів
Для перевірки працездатності всіх виправлень додано набір автотестів на базі `pytest` та `httpx`.
Щоб їх запустити, виконайте в кореневій папці проєкту:

```
pip install pytest pytest-asyncio httpx
pytest tests/ -v

```
